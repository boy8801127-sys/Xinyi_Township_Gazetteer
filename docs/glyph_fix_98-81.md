# 98-81 論文 PDF 文字層錯字修復紀錄

對象：`paper/碩博士論文/81-孫海與振昌木業-從今雲林縣口湖鄉至南投縣丹大林區(1917-2008).pdf`
（189 頁，內嵌字型 `DFKaiShu-SB-Estd-BF` 標楷體）

## 問題

PDF 文字層讀出來的字有一部分是錯的，而且錯字本身是**合法中文字**，不是亂碼：

| 讀到的 | 實際是 | 出現次數 |
|--------|--------|----------|
| 山 | 「（左引號） | 435 |
| （空白） | 」（右引號） | 435 |
| 中 | 山 | 281 |
| 撰 | 利 | 138 |
| 臺 | 由 | 130 |
| （空白） | 網 | 110 |
| 位 | 單 | 81 |
| ， | 責 | 61 |
| 」 | 北 | 52 |
| 識 | 認 | 46 |
| 」 | 庫 | 44 |
| 利 | 順 | 39 |

因此「昂貴」讀成「昂人」、「巒大山」讀成「巒大中」、「認為」讀成「識為」、
「山中小臺北」讀成「山中中小臺」、「國家文化記憶庫，網址」讀成「山國家文化記憶」，址」。
共 **2,292 字**（全文 86,793 個漢字的 2.6%）。有 6 個常用字（貴／百／認／由／順／撫）
在全篇 12.8 萬字裡出現次數是 **0**，全部被替換掉了。

錯誤模式：出錯的 glyph，其 ToUnicode 被填成了「該字後面那個字」的碼位——所以修正前的
文字常常出現「負負」「臺臺」「人人」這種重複字，那正是修復進度的檢查點（見下）。

## 為什麼不用 OCR 重抽

實測 Tesseract（繁中）全篇 OCR 對照後發現：OCR 會引入自己的辨識錯誤，而且比文字層更多。
50 個「OCR 與文字層不一致」的候選裡，**48 個是 OCR 自己錯**（「巒」→「蠻」、「闢」→「關」、
「洪廣冀」→「洪廣瘟」、「蔣中正」→「將中正」、「椬梧」→「栓梧」，動植物名尤其慘）。
文字層除了這批系統性錯字之外品質是好的，而且保有版面結構。

## 修法

PDF 內部的 **glyph id 是正確的**（同一字形永遠同一個 id），錯的只有 glyph → Unicode 那層。
所以建一份 `glyph id → 正確的字` 對照表即可還原，存在 `src/data/glyph_fix/98-81.json`（84 條），
套用程式在 `src/glyph_fix.py`。

### 對照表怎麼建出來的（四輪）

1. **衝突偵測**：同一字型內找「一個 Unicode 對到多個 glyph」→ 54 個字種、114 個字形。
2. **OCR 投票補漏**：衝突偵測抓不到「單一 glyph 也標錯」的情況（例如標成「利」的 glyph
   其實全部是「順」，因為真正的「利」被標成「撰」了）。用 Tesseract 全篇 OCR 與文字層
   逐頁 difflib 對齊投票，補抓出 3 個。
3. **非漢字補漏**：前兩輪只掃漢字範圍，漏掉標點與空白——結果這裡藏著最嚴重的一批
   （435 個右引號和 110 個「網」字直接變成空白消失）。補抓 15 個。
4. **重複字檢測**：修正後掃描連續重複的漢字（「握握」「勢勢」），這是「標成後一個字」
   這種錯誤模式下修正不完整的信號，補抓 6 個（掌／弱／緬／渦／鏡／堵）。

**所有候選一律裁切原始頁面的字形圖人工看圖判定**，並用出現處的上下文交叉驗證；
OCR 只當篩選器，不當判定依據。

### 配對機制

`get_texttrace()`（有 glyph id）與 `get_text("rawdict")`（有行結構）的字元序列**對不齊**——
前者會多抓到重複繪製的標題（PDF 用兩次繪製做粗體）。改用**字元 bbox 座標配對**，
實測 86,450 個漢字 100% 命中（漢字在兩邊的 bbox 完全相同）。

### 迴歸驗證

用空對照表跑 `build_fixed_page_lines()` 產出的段落，與原流程 `_iter_page_lines()` 的結果
**逐字完全相同**（733 段），確認這條管道除了換字之外沒有任何副作用。

## 已知未解

`gid 3326` / `gid 5730`（「開始大□□辦理集團移住」，推測原文是「大規模辦理」）字形在
規／郭、模／謨之間無法判定，保守起見維持原標注不修，影響 2 個字。

## 之後遇到同類 PDF

`src/glyph_fix.py` 是通用的，只要新增一份對照表 JSON 即可：

```bash
python -m src.export_paragraphs_single_paper "paper/碩博士論文/XX-....pdf" --glyph-fix XX-YY
```

判斷某篇 PDF 有沒有這個問題，最快的檢查是**統計常用字出現次數**——若「的」「是」「由」
「認」「百」這類字出現 0 次，就是中獎了。
